# 来源分级与工作台可读性调整

日期：2026-09-15。本文记录本轮置信度规则和工作台文案调整。

## 规则

- 一个已确认的一手来源，可以支持注明出处的产品说明和官方价格；仍需完整原文、逐字引用、数字校验和语义支持。
- 官方仓库必须在开题范围中明确到仓库根路径；仅写 github.com 不足以证明官方身份。Issue、讨论区和论坛内容不因托管在官方域名下而自动成为官方说明。
- 厂商性能宣传标为“厂商自述”，用户反馈标为“个别用户反馈”。增加转载来源不会把这两类陈述自动升级成普遍事实或独立实测。
- 真正影响事实可信性的审计问题仍阻止相关结论使用；普通补充备注不冻结全部结论，也不触发无意义的补搜。
- 报告允许“已完成，包含已知缺口”。未发现有依据的机会建议不再等同研究失败。每个竞品至少需要一项产品事实依据；用户明确勾选的必答项目必须有依据，技术中断仍标为未完成。
- 后台发布接口重新计算同一套规则，核对结论版本与来源等级，不仅信任前端状态。

## 工作台

主界面使用“制定研究计划、收集资料、提炼结论、核对结论、整理报告”等阶段名称。

结论分别显示“官方资料说明、厂商自述、个别用户反馈、多个来源支持、仍需核实”，并解释这些标签能证明什么。普通用户无需理解 Claim、Evidence、entails、Batch Item 等内部术语。

页面说明“缺少资料不代表产品没有这项能力”。来源数量不再被当作可信度，筛选评分放到展开详情中，明确不是正确概率。模型额度显示使用比例，并说明它不是完成进度或实际费用。

原始错误、任务编号和协议字段保留在关闭的技术详情里；主界面给出可理解的原因和下一步。报告使用“结论 1、资料 1”作为阅读标记，原始关联 ID 继续保存在结构化数据中。

新建研究可以勾选“必须回答的比较项目”；开题确认会展示官方域名、官方仓库和必答项目。

## 迁移与验证

新增 `ci_0011`，保存 Claim 的来源等级、批准的仓库地址和必答项目。旧的单来源结论不会仅靠迁移被自动升级；需要重新核对后使用。Gateway 下次启动自动迁移，本轮不改写历史报告。

验证包含官方单来源、性能自述、论坛反馈、官方仓库与 Issue 区分、非阻断备注、包含缺口的报告发布、必答项目缺失时拦截，以及工作台来源解释和必答项目表单。

最终结果：

- 相关后端回归 **239 passed in 25.77s**（调查子系统、Gateway 服务与 harness 边界）。
- 前端 **5 项测试通过**，包括工作台 DOM、部分发布、来源等级解释和必答项目表单。
- 前端 `pnpm check`（ESLint + TypeScript）通过；后端改动的 Ruff lint/format 和 `git diff --check` 通过。
- 完整离线工作流验证：只有一个官方来源时可完成；已有基本事实、其他项目缺资料时以“已完成，包含已知缺口”交付，且不触发补第二域名的返工。原有缺竞品补采、错误结论修订、引用及预算测试继续通过。
- 全库普通测试仍在 Windows 的 `os.geteuid` 调用处收集失败；严格 I/O 套件为 115 passed / 5 failed，与此前记录的三项 POSIX 权限、一项 Lark 调用、一项技能导出平台问题一致。这些不是本轮新增失败，未宣称全库通过。

本轮没有更改或绕过引文、数字、价格、冲突、归属和预算硬约束。真实 Provider 的准确率仍需在配置完善后测量；本轮验证不宣称模型置信度已完成统计校准。

补充边界：多个官方域名不自动等于独立验证；官方域名下明显的社区、用户视频和讨论页面不按官方产品说明处理。报告里的来源等级也传递给报告编写模型，避免在机会建议中把厂商宣传当成独立事实。
