# 竞品研究置信度门槛复核

日期：2026-09-15。性质：针对当前门槛的评估与调整建议；本轮未修改业务规则。

后续状态：本文建议已由下一轮实现落地，见 [来源分级与工作台调整](COMPETITIVE_RESEARCH_CONFIDENCE_AND_WORKSPACE_ZH.md)。以下保留当时评估依据。

## 结论

当前有几处门槛过于一刀切，会损失可用结论并增加补搜成本。问题主要在结论晋级与报告完整性判定，并不是某个 0–100 分数设得太高。现有 credibility_score 是启发式来源评分，不能当作已校准的正确概率。

上一轮将模型提交的所有 Claim 强制设为 material=True，解决了模型自行降低关键结论要求的问题，但同时使普通事实也必须满足两个独立域名，属于过度收紧。应由服务端按事实类型和断言范围选用证据规则。

## 当前过严之处

1. `orchestrator.py::_apply_claims` 强制 material=True；`repository.py::apply_audit_verdicts` 因此要求全部新事实至少两个独立域名。官方价格页、指定版本的 Release、官方文档陈述等信息，第二来源不一定增加验证价值，还可能更旧。
2. `quality.py::claim_is_eligible` 将任意开放 Issue 都作为阻断条件，不区分严重程度；claim_id=None 的开放问题甚至影响全部 Claim。应明确区分阻断事实可信性的问题与非阻断备注。
3. `render_grounded_report` 因任意 Coverage 缺口、开放问题或没有机会假设就标记 partial。执行是否完成、覆盖是否充分、个别结论是否可靠被混为一体。没有发现可辩护的机会，本身也可以是合理研究结果。
4. 候选准入主要依赖名称与维度词匹配，可能漏掉别名、隐含表达和其他语言的相关材料。模糊候选可以留待语义复核，但不得直接晋级为已验证事实。

## 建议采用的证据规则

| 结论类型 | 可接受依据 | 报告措辞 |
| --- | --- | --- |
| 官方列示的套餐价格、支持平台、已发布功能 | 一个已确认归属的一手来源，原文支持，注明时间、版本和适用条件 | “官方价格页列示……”“该版本发布说明列出……” |
| README 中的性能或效果宣传 | 一手来源可证明厂商或项目作出了该陈述，不能直接证明实际效果 | “项目声称……”；实际效果另待测量 |
| 社区反馈或单个 Issue | 一条可追溯记录可证明某用户报告过某问题 | “有用户报告……”；不推导普遍发生率或系统性缺陷 |
| 关键比较、广泛概括、争议性结论 | 独立交叉验证或适当的可复核一手测量；来源数量不能代替方法与适用范围检查 | 证据不足时缩窄断言、保留条件或列为未知 |
| 产品机会与战略建议 | 明确引用已确认前提，并给出待验证假设和行动 | 明确标识为判断或建议 |

“官方陈述已确认”和“实际效果已独立验证”应作为不同证据状态，而不是都归为同一个高置信度。

## 应继续保持的硬门槛

- 无关材料不能支撑目标竞品结论。
- 引文、快照和数字必须真实对应，不能捏造或偷换计费周期。
- 结论不得超出证据支持范围；部分支持应触发缩窄或拆分。
- 实质冲突及阻断性审计问题必须处理或显式保留，不能静默忽略。
- 未知不能被填成确定事实，预算不足也不能冒充完整研究成功。

## 调整后的报告状态

分别呈现执行状态、问题覆盖和结论证据等级。允许“研究已完成，存在已知缺口”的可用报告。技术中断、核心问题未完成审计或核心交付缺失时仍应明确标为未完成。

后续调整应先增加回归：官方单来源事实可通过；官方自述不能升级为独立实测；单个 Issue 不能证明普遍性；非阻断备注不冻结全部结论；可接受缺口与缺少机会假设不自动等同执行失败。保留原有噪声、虚构引文、过度概括和冲突用例，再用真实任务衡量误放与误拒。
